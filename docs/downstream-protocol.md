# 下游 WebSocket 协议

`server` 面向本机程序提供一个房间的实时事件流。启动方法见 [README](../README.md)。
默认地址为 `ws://127.0.0.1:8080/ws`，通过 `BRIDGE_LISTEN` 指定 IP 和端口。
仅 `/ws` 接受 WebSocket 升级；其他路径返回 HTTP 404。当前没有独立的服务访问 token，
默认使用回环监听，本机客户端以主播身份码发起订阅。

## 接入

握手后 10 秒内发送一条 JSON 文本消息：

```json
{"type":"subscribe","code":"主播身份码"}
```

身份码去掉首尾空白后必须非空；房间号不能替代身份码。每条连接只允许订阅一次，
换房间或恢复连接时新建 WebSocket 并重新发送 `subscribe`。关闭连接即取消订阅。
身份码放在首条消息中，不放在 URL 中；服务器不在响应中返回身份码、Access Key 或上游鉴权正文。

服务先完成平台开启、上游建连和鉴权，再返回：

```json
{"type":"ready","room_id":123,"game_id":"场次 ID"}
```

`ready` 必定先于本连接的事件。平台 HTTP 请求最多等待 10 秒；上游的每个候选地址
分别有 10 秒连接及鉴权超时，接入过程没有另设总超时。

## 服务端消息

所有业务消息使用 JSON 文本帧，`type` 区分用途：

| `type` | 其他字段 | 含义 |
| --- | --- | --- |
| `ready` | `room_id`、`game_id` | 接入成功，可以开始消费事件 |
| `event` | `room_id`、`cmd`、`data` | 订阅房间的一条直播事件 |
| `lagged` | `skipped` | 广播缓冲覆盖了此订阅的未读事件；随后继续推送 |
| `error` | `code`、`message` | 请求无效或接入失败；随后关闭连接 |
| `closed` | 无 | 会话结束或服务退出；随后关闭连接 |

事件示例（`data` 在这里省略了其他已声明字段）：

```json
{
  "type":"event",
  "room_id":123,
  "cmd":"LIVE_OPEN_PLATFORM_DM",
  "data":{"room_id":123,"msg":"你好","msg_id":"...","timestamp":1790000000}
}
```

`cmd` 使用官方命令名。已知事件的 `data` 是当前 Rust 结构序列化后的对象，包含默认字段，
上游未声明的新字段会被现有解析器忽略；未知命令保留原始 `data`，缺失时为 JSON `null`。
字段含义见 [官方长链命令资料](open-live/websocket-commands.md)。客户端应容忍未知命令和新增字段。

`error.code` 有两个稳定值：

- `invalid_request`：JSON 格式、消息类型或身份码无效，首包超时，或重复订阅。使用关闭码 1008。
- `attach_failed`：平台开启、上游连接或接入完成失败。使用关闭码 1011。具体平台错误记录在服务端日志。

正常 `closed` 使用关闭码 1000。读写故障、消息过大或连接已断开时，可能直接断开，
客户端不能依赖最后一定收到状态消息。

## 分发与重连

同一个管理器中的同码客户端共享一场上游互动。每条下游连接独立读取容量为 256 条的广播缓冲，
慢客户端不会阻塞其他客户端或上游；收到 `lagged` 后从仍保留的事件继续。消息按接收顺序发送，
没有持久化、确认或历史补发，新订阅只接收加入后的事件。

`server` 在最后一个订阅者离开后保留上游 30 秒，继续接收事件及维护 WebSocket 和项目心跳。
30 秒内使用相同身份码重连，可复用原 `game_id`；无人订阅期间的事件不会回放。
宽限期到期后清理场次，再接入将重新开启。库的 `Manager::new` 和 `Manager::from_config`
仍默认立即清理；嵌入服务可以通过 `Manager::with_options` 设置 `ManagerOptions::idle_grace`。

`LIVE_OPEN_PLATFORM_INTERACTION_END` 先转发为事件，再发送 `closed`；普通
`LIVE_OPEN_PLATFORM_LIVE_END` 只转发，下游继续订阅。上游断开、项目心跳失效或服务主动退出
立即结束会话，不等待 30 秒。当前没有上游自动重连，客户端需要重新接入。

## 心跳与退出

服务端持续读取客户端的控制帧，自动响应 Ping；收到 `ready` 后，每 20 秒发送一次标准
WebSocket Ping，10 秒内未收到携带相同负载的 Pong 时断开。使用客户端 WebSocket 库的
控制帧处理能力即可，不需要发送 JSON 心跳。

握手、首包和单次发送最多等待 10 秒；客户端单帧和完整消息上限均为 8 KiB。
消息过大、发送超时或读取失败会释放订阅。进程通过 Ctrl-C 或 Unix SIGTERM 退出时，
停止接入，通知下游关闭，等待会话结束请求和全部连接任务收尾。
已经发出的接入请求仍会完成并释放结果，避免直接取消平台请求而遗漏场次清理。
