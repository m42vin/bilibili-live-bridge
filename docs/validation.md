# 本地故障验证与压测验收

本流程使用独立服务子进程、本地 HTTP / WebSocket 平台桩和假凭据，复用 `server` 的生产装配与共同驱动器。
子进程只在 `cfg(test)` 内替换源站和闲置宽限期，不给正式服务增加源站覆盖环境变量，不读取 `.env`。
默认测试不执行本流程；显式验收会发送 SIGTERM、SIGKILL，但只作用于本次创建并持有的子进程。

它验证协议、恢复、背压及资源生命周期，不代表真实 Bilibili、TLS 反向代理或目标部署硬件的性能上限。
真实平台联调边界见 [开发指南](development.md#上游健康与恢复验证)，探针与指标口径见 [运维观测](operations.md)。

## 环境与命令

需要 Rust stable、Cargo，以及允许回环监听和子进程采样的 Linux 或 macOS。
Linux 从 `/proc/<pid>/status`、`/proc/<pid>/fd` 采样；macOS 使用系统 `ps` 与 `lsof`，均只读取测试子进程。
缺少权限或采样工具会使验收失败，不把无法采样当作资源已经回落。

在仓库根目录执行：

```sh
# 完整故障矩阵，低速负载，默认四个快消费者、200 事件/秒、一秒/轮。
./scripts/validate.sh smoke

# Release 负载，默认八个快消费者、2000 事件/秒、三秒/轮。
./scripts/validate.sh load

# 延长观察，默认 60 秒/轮、10 轮；此命令约需十余分钟。
./scripts/validate.sh soak

# 先降低目标速率校验环境，再逐步增加；不要降低验收阈值掩盖失败。
BRIDGE_VALIDATE_CLIENTS=16 BRIDGE_VALIDATE_RATE=4000 \
  BRIDGE_VALIDATE_SECONDS=10 ./scripts/validate.sh load

# 心跳测试连续执行 100 轮真实线缆 I/O，虚拟活动时间共推进 16 秒。
cargo test --locked -p bridge-native --lib heartbeat_repeatability -- --ignored --nocapture
```

依赖已缓存时可设置 `CARGO_NET_OFFLINE=true`。macOS 如开发目录选择影响工具链，可只为命令设置
`DEVELOPER_DIR=/Library/Developer/CommandLineTools`，不需要修改全局开发目录。

`validate.sh` 始终使用 release 测试目标，精确选择 `server::validation::acceptance`；不要使用无过滤的 `--ignored`，
内部 child 用例需要父进程提供隔离配置。子进程使用两个 Tokio worker，发生器和消费者在另一个四 worker 的父进程中。
报告的吞吐与延迟包含父进程、序列化、回环网络和消费者处理，不等于仅服务器内部处理时间。

## 参数与输出

| 环境变量 | load 默认值 | 范围或含义 |
| --- | --- | --- |
| `BRIDGE_VALIDATE_CLIENTS` | 8 | 1–64 个快 ACK 消费者，另加一个故意不 ACK 的慢消费者 |
| `BRIDGE_VALIDATE_RATE` | 2000 | 1–50000，源事件/秒，按 32 条以内批量写入 |
| `BRIDGE_VALIDATE_SECONDS` | 3 | 1–3600，每轮发生器持续时间 |
| `BRIDGE_VALIDATE_CYCLES` | 3 | 3–100，暖机之后的验证轮数；额外先运行一轮同规模暖机 |
| `BRIDGE_VALIDATE_PAYLOAD_BYTES` | 256 | 1–8192，事件中的测试字符串字节数，不含 JSON 和协议开销 |
| `BRIDGE_VALIDATE_REPORT` | `target/validation-load.json` | 脚本按 profile 设置；相对路径按仓库根目录解析，相同路径覆盖上次结果 |

smoke 只改变快消费者数、目标速率、每轮时长与载荷，仍运行全部故障场景和至少三轮回落验收。
soak 改变每轮时长与轮数，其余参数继续允许通过环境变量覆盖。
每轮的 `RATE × SECONDS` 必须至少为 64，确保慢消费者确实压满 ACK 窗口；不满足时直接拒绝参数。

JSON 报告包含 OS、架构、构建模式、参数、模型设置、验收阈值、冷启动与暖机基线、每轮观测峰值及收尾值、
交付量、有限直方图 P95 上界、最大延迟、故障耗时和各场景结果。任一判据失败则命令非零退出，报告 `passed=false`。
延迟以父进程共用的单调时间原点计量，不依赖墙钟同步；只保留有限直方图，不按事件积累数组。
RSS、FD 和任务峰值是约 500 毫秒采样得到的观测峰值，不能声称捕获了所有瞬时峰值。
脚本在编译前先写入 `passed=false` 的占位报告，避免编译、参数或启动失败时误读上次成功记录。
以本次命令退出状态和完整报告为准；直接执行 cargo 用例时不会经过该占位保护。

## 模型配置

为了缩短可重复演练时间，测试子进程采用以下显式设置，而非全部生产默认值：

| 设置 | 验收值 |
| --- | --- |
| 闲置宽限期 / 结束日志保留 | 1 秒 / 2 秒 |
| 日志字节预算 | 8 MiB |
| 退出总预算 | 2 秒 |
| 上游心跳 / 发送 / 活动期限 | 1 / 1 / 3 秒 |
| 原场次恢复预算 / 初始与最大退避 | 5 秒 / 100 与 200 毫秒 |
| 项目心跳 / 恢复预算 | 1 秒 / 20 秒 |
| 平台 HTTP 请求总超时 | 生产原值 10 秒，真实等待此期限 |
| start 失败冷却 | 1 秒 |
| 并发连接 / 握手 / 待接入 | 256 / 64 / 128 |
| 开场 / 会话 / 每房订阅 | 16 / 16 / 128 |
| start 速率与突发 | 各 100 次 |
| 下游业务消息速率与突发 | 各 100000 条，用于避免 ACK 准入遮挡源速率测量 |
| 回放速率 | 16 MiB/秒，突发容量仍为 1 MiB |
| 模拟远端心跳失效回收 | 5 秒；只代表本地模型，不代表 Bilibili 真实 TTL |

发送字节、单条响应、ACK 窗口等其余保护沿用实际配置与实现。
较短的日志保留用于确定地触发慢 ACK 消费者缺口，较短的闲置期用于反复观察收尾。
不得将这些参数直接当作生产推荐配置。

## 故障矩阵与判据

| 场景 | 明确注入或观察 | 必须满足 |
| --- | --- | --- |
| 高事件速率 | 一房多消费者，暖机加至少三轮负载 | 每个快消费者的桥侧序号和源索引连续，同码只有一次 start；有效源速率至少为目标的 80%，P95 延迟上界不超过 1000 ms |
| 慢消费者 | 一个客户端不 ACK，跨越日志保留期限并追加事件 | 确认实际压满且不突破 64 条窗口；明确返回 resume_unavailable，快消费者全部完成 |
| 集中重连 | 同时丢弃所有快客户端连接，离线追加七条，按各自原游标并发续传 | 同一场次和流，每个客户端补齐七条；不重复 start，不隐式清游标 |
| 上游 TCP 断线 | 不发送 WebSocket Close 直接断开，暂停新连接鉴权以固定观察窗口 | 进入恢复，全局 ready 仍为 200；原鉴权恢复成功并继续有序交付，不 start 或 end 原场次 |
| 上游静默 | 忽略真实上游协议心跳回复，暂停恢复鉴权 | 确认桩收到了被忽略的心跳，并实际经过活动期限；解除故障后同场次恢复有序交付 |
| 平台超时 | 一次 start 不回复，等客户端断开 | 约十秒返回明确接入失败，记录 timeout；接入、开场、会话名额全部释放 |
| 平台限流 | 项目心跳返回真实 HTTP 429，再解除 | 恢复登记非零、ready 保持 200；解除后恢复登记归零，原场次不被关闭且继续有序交付 |
| SIGTERM | 活动连接时向服务子进程发送信号 | service_restarting，收尾期间 ready=503、live=200；完成关闭后成功退出，已知场次 end 一次 |
| SIGTERM 且 end 阻塞 | 模拟平台记录 end 后不回复 | 两秒退出预算生效，约五秒墙钟保护内非零退出，日志明确清理可能未完成 |
| 强制终止 | 对测试服务发送 SIGKILL 并 wait 回收 | 不能冒充优雅关闭，远端模型仍保留场次；进程退出释放本机资源，不保证远端 end |
| 重启 | 启动全新子进程，先携旧游标重连，再显式首次订阅 | 旧游标返回 resume_unavailable 且零次新 start；模型确认旧远端失效后，显式订阅才创建新流 |

本地桩具有有限连接、指令队列和日志环；每批事件等待实际上游写入后才继续，不向父进程堆积无界负载。
上游恢复阶段暂停鉴权由桩的 gate 控制，避免靠固定 sleep 猜测是否进入恢复。
测试进程在失败路径也被 kill、wait 并回收 stderr 读取线程。

## 回落与泄漏判据

每轮完成后按事实轮询连接、握手、待接入、开场、会话名额、订阅数与发送字节，全部必须归零。
等待已结束日志的模型保留期限之后，显式访问旧游标驱动原有惰性清理；该访问必须失败且不能新开场。
连续三次采样确认日志字节、流数及名额为零后，才读取收尾 RSS、任务数和 FD。

暖机允许建立连接池、常驻项目心跳调度任务和分配器缓存。每轮收尾要求：

- Tokio 活动任务数不超过暖机基线加 2；该指标包含当前采样请求，且多线程读数不是跨任务原子快照。
- 数字文件描述符不超过暖机基线加 4，允许采样及网络关闭的短暂波动。
- 收尾 RSS 不超过暖机基线加 64 MiB，且后续轮次不超过第一轮验证收尾值加 32 MiB。
- 日志和资源名额严格为零，不能用 RSS 阈值掩盖逻辑资源仍被持有。

报告同时提供冷基线、观测峰值和收尾值，便于检查实际是否下降。系统分配器可能保留已经释放的页，
因此 RSS 不要求精确回到冷启动值；“暖机后未持续增长”与“所有页已归还 OS”是不同结论。
三轮短测不能证明长期无泄漏。目标机器应额外执行 soak，结合实际 SLO、载荷分布和内存限制重新评估。

## 心跳时序稳定性

旧线缆心跳测试在真实墙钟下只有 100 ms 活动窗口，并发编译或系统调度迟到会误触发失活。
现在在暂停的 Tokio 时间下建立真实 WebSocket，逐步推进 20 ms；每次确认真实心跳已送达、回复已被消费、
活动截止时间确实刷新，再推进下一步。I/O 持续轮询防止暂停时钟因空闲自动跳到失活期限，另用三秒墙钟保护防止测试挂死。
八轮虚拟心跳跨越原来的 100 ms 窗口，最后正常关闭；重复用例执行 100 次，不通过放宽被测期限掩盖问题。

本次故障演练还验证了 ResetWithoutClosingHandshake：它表示 TCP 丢失，归为可恢复 Transport，
其他传输协议错误仍终止；单元测试和本地原场次重连同时覆盖该边界。

## 本次实测记录

2026-10-20，在 macOS / aarch64、Rust 1.98.1 的 Release 模式下执行默认 load，以及以下十轮短时循环：

```sh
CARGO_NET_OFFLINE=true BRIDGE_VALIDATE_SECONDS=3 BRIDGE_VALIDATE_CYCLES=10 \
  ./scripts/validate.sh soak
```

两次均为八个快消费者加一个不 ACK 的慢消费者、256 字节测试载荷，每轮 6000 个源事件。
下表排除暖机轮；任务和 FD 为每轮收尾读数，RSS 单位为 KiB。

| 项目 | 默认 load，三轮 | 短时循环，十轮 |
| --- | --- | --- |
| 有效源速率，约 | 1999.5–2003.3 事件/秒 | 2001.5–2004.1 事件/秒 |
| 快消费者交付总量 | 144000 | 480000 |
| 各轮 P95 延迟上界 | 5–10 ms | 2–10 ms |
| 暖机 RSS → 最后一轮 RSS | 14512 → 14928 | 14368 → 13632 |
| 收尾任务 / FD | 3 / 11 | 3 / 11 |
| 名额、发送字节、订阅、日志 | 全部归零 | 全部归零 |
| 集中重连与其他故障后的任务 / FD | 3 / 11 | 3 / 11 |
| 全部故障场景 | 通过 | 通过 |

两次平台超时均约 10.00 秒；静默恢复约 3.03 秒；正常 SIGTERM 约 16–27 毫秒退出，
阻塞 end 时约 2.02 秒以失败状态退出。SIGKILL 后确认进程已回收且没有 end，重启后的旧游标明确失败。
平台限流、上游断线和静默解除后，均在原客户端验证了序号连续的新事件。
报告分别位于 `target/validation-load.json` 和 `target/validation-soak.json`，不提交到版本库，后续运行会覆盖。

这是十轮各三秒的短时回落验证，没有执行默认每轮六十秒的 soak 或数小时演练，
也没有执行 Linux 采样与真实平台联调。RSS 收尾值符合本次阈值，不能据此推断长期不会泄漏。
